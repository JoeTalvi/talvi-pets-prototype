## Proximity rule (`src/sim/rules/greetings.ts` `stepGreetings`)
- Every tick, every `greetings` cooldown counts down by `dtMs` (floor 0), in any scene.
- A meeting can start only when `scene.kind === 'street'` and `!inputFrozen` (dialogue, celebration, project arrival, site arrival, design mode; order fork 4). While frozen no meeting starts and no cooldown is written; the pets keep wandering.
- Candidates: the street pets (`streetPets(content, state)`, WORK-035-1) whose phase is `idle` or `walking`. Pairs in content order (a before b). A pair qualifies when `hypot(a − b) <= greetRadiusRu × roomUnitPx` (1.5 × 240 = 360 px, inclusive) and its cooldown entry is absent or 0. A pet joins at most one meeting per tick: the first qualifying pair in order wins, a third pet waits. The countdown runs first, so the tick that brings a cooldown to 0 is already eligible (60 000 ms after the last greeting).

## The meeting (`startMeeting(content, state, a, b)`)
- Each pet: `phase 'meeting'`, `facing` toward the other (right when it stands left of it, left when right, unchanged at equal x), `timerMs = greetMeetingMs` (2000), `target null`, `verb null`, `reaction null`; one `pet.phaseChanged` each (a then b).
- Emotes: one draw per pet (a then b), each on that pet's own `rngState` (TECH-008), over the band weights of `compatibility[a][b]` (absent = 0) from `tuning.greetEmoteWeights`.
- `greetings["a|b"] = { cooldownMs: greetCooldownMs }`; emit `greeting.played { petA, petB, emoteA, emoteB }`; then the `greeted` rule for a then b (WORK-036-1-mec-009.md). No `pet.reacted`.
- End: no new branch. A `meeting` pet's timer counts down; on expiry the existing `afterBubble` path returns it to `idle` with a fresh `idleMs` roll (its `verb` is null), after which it wanders again. A meeting interrupts a walk (target cleared), so the next walk may resume the same wander point.
