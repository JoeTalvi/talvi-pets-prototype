- R3 (ownership): inventory is a count of copies per type (`inventory.counts`), copies in hand only. A type is "granted" once it has a key; the key is never removed.
- R4 (starter set): `starterSet` is a list of `{ typeId, count }`; the initial counts are those items in file order (six types, one copy each).
- R5 (grants): `grantItems(content, state, items, source)` adds each item's `count` to `counts[typeId]`, appending a new key at the end (first-grant order); one `items.granted { typeId, count, source }` per item; an empty list emits nothing. Every award grants copies, including a type already owned (no de-duplication).
- R6 (sources): `phase` (collectRewards / skipWait: the items of phases fromPhase+1..toPhase, phase then list order), `heart` (a want's `items` reward entry), `debug` (`debugGrantCopies`, `debugUnlockAllTypes`). `debugUnlockAllTypes` grants one copy of every type with no key, file order; a second use grants nothing.
- R7 (chooser): `chooserTypes` lists the `counts` keys of the slot's size class in first-grant order, zero-count types included; `copiesOf` gives the copies in hand.
- R8 (ownsTag): a tag is owned when some granted type carries it, whether in hand or placed.
- R10 (placing spends): placing spends one copy; a type at zero is rejected `noCopiesLeft`, except a same-type replace (which re-uses the placed copy and changes no count).
- R11 (removing returns): removing, or replacing by a different type, returns one copy of the type that left.
